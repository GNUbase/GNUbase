# PipeWire

The Linux audio backend `pipewire` (#37), in `src/platform/audio/pipewire.cpp`. It comes first in `audio.devices` on Linux, before the dummy backend; JACK (#38) goes next to it in `makeBackends()`. Like every backend it is reached through `audio.devices`, `audio.setDevice` and `audio.get`, or `--audio pipewire` in headless mode.

- **A filter node.** GNUbase joins the PipeWire graph as one node named `gnubase`, with an input port per input channel and an output port per output channel (32-bit float DSP ports), as a JACK client would. It isn't a stream: there is no resampling or channel mixing in between, and PipeWire's session manager doesn't link it. GNUbase links the ports itself, output channel *n* to the sink's *n*th playback port and the source's *n*th capture port to input channel *n*, in the order of the nodes' ports. A sink's monitor ports are no capture ports, but a virtual source's capture ports are monitor ports and count. The links go away with the device.
- **Devices.** A device is a sink, optionally with a source, as with WASAPI: `default` is the default sink with the default source (the session manager's defaults, from the `default` metadata; the first sink if it names none), a sink's `node.name` is that sink alone, and `<sink>|<source>` pairs the two. Sinks are the nodes of media class `Audio/Sink...` with playback ports, sources those of `Audio/Source...` with capture ports, and a duplex device (`Audio/Duplex`, the pro-audio profile) is both, so it opens as `<node>|<node>`. Channel names are the ports' `audio.channel` (`FL`, `FR`, ...). Without a daemon, `audio.devices` reports the backend with an error.
- **Sample rate.** The graph has one rate. A device lists the rates the graph may switch to (`clock.allowed-rates` in the `settings` metadata, and the current `clock.rate`) and opens at the current one by default. The node asks for its rate with `node.rate` and `node.force-rate` while it runs, so other clients follow it. If another client forces a different rate anyway, the device plays silence rather than at the wrong speed and logs a warning once.
- **Block size.** The node asks for its block size as the graph's quantum (`node.latency`), but the graph settles on the quantum that suits all of its clients, within `clock.min-quantum` and `clock.max-quantum`. Each cycle is processed in blocks of at most the block size, as with WASAPI, so any block size up to 8192 works; by default it is `clock.quantum`.
- **Real-time thread.** The node processes on PipeWire's data thread (`PW_FILTER_FLAG_RT_PROCESS`), which PipeWire's client configuration makes real-time through its RT module or RTKit. Output ports are zeroed before the engine's callback runs, inputs that have no buffer read silence. `stop()` returns once the data thread is out of the callback and the node is inactive. Opening a device leaves the node inactive, so a device that is only open doesn't hold the graph's rate.
- **Latency.** PipeWire tells each port the latency of what it is linked to (the `Latency` parameter): the output ports the latency down to the sink, the input ports the latency up from the source, in quanta, frames and nanoseconds. `audio.get` reports those in frames once PipeWire has told them, a quantum each before that. When a port's latency arrives or changes, or the graph's quantum changes (the audio thread signals a loop event, which only writes to an eventfd), the device reports a latency change and the engine moves the record offset with it (`audio.updateLatency`, docs/features/latency-and-monitoring.md).
- **Resets.** The device asks the engine for a reset (`audio.reset`) when its sink or source goes away, when the daemon goes away or the node fails, and, for `default`, when the default sink or source changes.
- **Tests.** The device contract suite (`tests/device_tests.cpp`) runs against PipeWire where a daemon runs, and is skipped elsewhere; with `pw-cli`, the test then adds a sink, opens it and removes it, and checks that the device asks for a reset. The `linux-x64-gcc` CI job starts a headless daemon with WirePlumber, a null sink and a null source (`tools/start-pipewire.sh`) and sets `GNUBASE_REQUIRE_PIPEWIRE=1`, which makes the tests fail rather than skip without it.
