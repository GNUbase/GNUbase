# Input and output busses

The connections between the project and the audio hardware (#43, reference manual pp. 35–53). Busses belong to the project: they are saved with it and their changes are undone like any other. The audio connections window comes with the mixer milestone; everything it does is a command here.

- **Busses.** An input bus brings audio from device inputs to audio tracks, an output bus takes the mix to device outputs. Each has a name and a format: mono, stereo or a surround format ([channel-formats.md](channel-formats.md)). `bus.add` adds one; without a name it is named after its format and direction ("Stereo In", "5.1 Out", then "Stereo In 2" and so on). `bus.set` renames one, changes its ports or makes it the main mix; `bus.remove` removes one together with its child busses, and disconnects the channels that used them.
- **Ports.** Each channel of a bus uses a device port, given by name: the device's own channel names, as `audio.ports` lists them ("Input 1", "Analog Out 3" and so on; a channel without a name is "Input n" or "Output n", and repeated names get " #2", " #3"). `ports` in `bus.add` and `bus.set` has one name per channel, or an empty name for a channel that uses no port. A bus that never got ports takes consecutive device ports in bus order: as many as the busses of its direction before it have channels are skipped. A new project's busses work that way on any device, and so do projects saved before ports existed. `bus.set` with `ports: []` goes back to that.
- **Non-exclusive ports.** A port can serve several busses. An input port feeds every input bus that uses it; output busses that share a port add up there, in bus order, so the result is the same every time. Ports that no output bus uses stay silent.
- **Names make projects portable.** Ports are stored by name, not by number, so a project finds its ports on another device whose ports have the same names, in any order (p. 41). Names that the device doesn't have are **missing ports**: their bus channels stay silent, and the project keeps the names, so it plays as before once it is back on its own device. `audio.ports` lists the device's ports with the busses that use each one (the device port menu, which shows them in brackets), each bus's ports on this device, and the missing ports with their busses. `bus.remapPorts` re-routes missing ports to ports of this device (the reference's missing ports dialog, p. 132): it replaces port names in every bus of a direction at once, one undo step. A bus on consecutive ports has no names to miss; where its ports run past the device's, e.g. an old project on a smaller device, `audio.ports` lists it under `beyondDevice` with the channels that stay silent, and `bus.set` gives it ports. Giving ports names of their own (the reference's "Show As") and hiding them come with the studio setup (#79).
- **Main mix.** One output bus is the main mix, the default output: new audio, group and effect channels are routed to it (p. 43). The first output bus becomes the main mix; `bus.set` with `mainMix: true` makes another one it. When the main mix is removed, the next output bus takes over. Busses report `mainMix`. With no control room (a later milestone), the main mix is also the **monitoring bus** (p. 45).
- **Child busses** route tracks to some channels of a surround bus, or record some of its channels (p. 43): a stereo track to the Ls and Rs of a 5.1 output bus, say. A child bus has a `parent`, a top-level bus of the same direction, a format, and `parentChannels`: the parent's channel each of its channels is, by index in the parent's speaker order. Without them, a child takes the speakers its format shares with its parent (a stereo child of a 5.1 bus takes L and R), and its name is its format with those speakers, such as "Stereo (Ls Rs)". A child bus has no ports of its own. In the processing graph an output child bus adds its channels to its parent's (`graph::GraphDesc::channelMaps`), and an input child bus takes its channels from its parent's, so a child is always where its parent is.
- **Renaming several busses** (p. 52): `bus.rename` gives a list of busses one name with an incrementing number or letter. The name ends in a number ("Out 1": "Out 2", "Out 3"; "Out 01": "Out 02") or in a space and a capital letter ("Bus A": "Bus B" up to "Bus Z"). The first bus listed gets the name as given; the others follow in bus order from there, and continue from the top.
- **Presets** (pp. 43–44): bus configurations of one direction, with their names, formats, ports and child busses. `bus.presets` lists three kinds: `standard` presets with one bus of a common format (mono, stereo, 5.1, 7.1), on the device's first ports; `hardware` presets made from the device's ports (as many mono busses as it has ports, and stereo busses on pairs of them); and the user's own, which `bus.savePreset` saves from the project and `bus.removePreset` removes. They are kept in the user setting `audio.busPresets`, for every project. `bus.applyPreset` replaces the project's busses of that direction with a preset's, one undo step: channels that used the old busses move to the new bus at the same place in the list, or to none (inputs) or the main mix (outputs) if there is none. A user preset named "Default" is applied to every new project (`project.new`); one that doesn't work, e.g. edited by hand, leaves the standard busses and a warning in the log. A user preset hides a standard or hardware preset of the same name.
- **Events.** `bus.added`, `bus.changed` and `bus.removed`, as for every document change; a new main mix changes two busses. The device's ports change with `audio.setDevice`, which emits `audio.changed`: clients ask `audio.ports` again then, and after `project.load`, to find missing ports.
- **DAWproject** has output busses as `master` channels and no input busses. The main mix is written as the first master channel, which other applications take as their main output, and a channel routed to a child bus is routed to its parent there. Ports, input busses, child busses and which bus is the main mix are in GNUbase's extra entry. A project read from `project.xml` alone gets the first master channel as its main mix and automatic ports.
- **Real time.** The audio engine works out each bus's device channels when it compiles the graph, from the device's port names, and hands them to the audio thread with the graph; the audio thread only copies and adds samples.
