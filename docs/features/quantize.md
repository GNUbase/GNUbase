# MIDI quantizing

Quantizing notes to grids and grooves (#132).

- **MIDI quantizing** (`src/engine/midi/quantize.h`, #132) moves note starts or ends toward a grid or a groove, or sets note lengths. A grid is a note value (straight, triplet or dotted) with optional tuplets and swing; it is in project time and starts again at every bar, so it follows time signature changes. A groove is a list of positions repeating every groove length, given directly or extracted from a MIDI part. Strength, catch range, safe range, randomizing (seeded per note, so the same seed gives the same result on every platform) and, for grooves, pre-quantizing, max. move and velocity and length strengths shape how notes move. A quantized note keeps its timing from before it was first quantized and what quantizing made of it (`Note::origin`): quantizing again starts from the original unless it is soft (iterative), `quantize.reset` puts the original back and `quantize.freeze` drops it. A note whose timing no longer is the quantized one was changed by other means, such as `note.set`, so its original no longer counts; other commands don't need to know about quantizing. The commands are `quantize.*` (`quantizecommands.h`), registered through `ProjectModel::addEdit`. The project keeps its current quantize settings and the auto quantize switch, saved in the DAWproject extension entry but not undo steps; recording will apply auto quantize. Presets (the factory grids and the user's, with grooves) belong to the user, not to a project, so every project has them. The user's presets are user settings (#278, see [settings.md](settings.md)): `quantize-presets.json` in the settings folder (`quantizePresetsFormat()`), a versioned file whose setting `quantize.presets` lists each preset's name and settings as `quantize.presets` returns them, groove points included; factory presets aren't written. The engine reads it when it starts and saves it whenever a preset is saved, renamed or removed. A preset that can't be read (settings out of range or of a newer GNUbase, no or a repeated name, a factory preset's name) is skipped with a log message and stays in the file, so the GNUbase that wrote it still has it. Its name stays taken: saving or renaming a preset to it fails, and `quantize.removePreset` removes it. `quantize.presets` reports the file, whether changes are saved (`readOnly`, as while the file belongs to a newer GNUbase) and the problems found when it was read, skipped presets included. Several GNUbase processes can share the file: each change starts from the presets in the file as they are then (`settings::Store::modify`), so no process drops another one's presets, and the process sees them from then on, even if the change fails. If the file can't be written, the command fails and nothing changes.
